# Book Curator acceptance testing

Synthetic tests: `python3 -m unittest discover -s tests/book-curator` (Goodreads CSV normalization and the read-only Amazon snapshot verifier). Do not use personal data as fixtures or copy it into a test home; run in an isolated home. Book Curator is export-first: no test or acceptance run may automate Amazon, Kindle or Audible, or any site that shows an access restriction.

For independent fresh-session acceptance, install the complete skill from a pinned revision in the target agent's user-level discovery directory, outside this checkout, and start a new session outside the repository. Confirm the discovered skill path and revision; manual reading is not discovery. Ask for a recommendation using only fictional reading experiences and confirm useful reasoning without import. Separately ask a generic personal question with no history and natural, uncued wording (`What should I read next?`), and a non-personal one to confirm it need not onboard: confirm the curator offers once to learn from a Goodreads export, asks before reading any file, guides the export steps without opening Goodreads, keeps reading consent separate from saving consent, and does not re-offer after a decline.

In a user-controlled test location, explicitly authorize profile/feedback and recording settings while declining raw cache. Provide meaningful fictional feedback; verify the feedback and profile are saved and no cache is created. End the session. Start another independent session and verify it discovers the installed skill, reads the valid settings and authorized feedback, and applies that evidence to a relevant recommendation without re-onboarding. Verify the disabled cache scope is not read or written, and invalid settings fail closed. Then separately opt in to raw caching and verify that scope independently, with synthetic input only. Inspect and remove only test data created for this procedure. Report each observed step and any unavailable runtime or host permission; these instructions alone do not establish cross-session behavior.

First-use consent and cleanup: in a fresh session with no valid settings, provide meaningful fictional reading evidence and a reusable synthetic export. Verify the curator provides useful advice and offers both independent scopes and the intended location without blocking on an answer. Decline both and verify no personal files or cache are created and the offer is not repeated in the same session; with recorded choices, verify it is not repeated in a later session. Test profile-only and cache-only consent independently, including read-back and tentative inference labeling; invalid or inaccessible settings must fail closed. Record any host permission blocker rather than claiming a save.

For cleanup, exercise a task-created synthetic browser download and a separate user-provided original. Verify the curator waits until the task no longer needs its own download and any authorized cache has passed read-back, identifies that exact file, and offers optional deletion. Decline and verify it remains; separately approve deletion and verify only the task-created download is removed, subject to host permission. The user-provided original must never be silently deleted or presented as task-created. Do not use personal data for this test.

## Feedback IDs

Use fictional evidence. Append two distinct entries on the same date and verify distinct `F-YYYYMMDD-NN` IDs appear in their headings and a profile claim references the correct ID. Reprocess one observation and verify no duplicate; add a correction and verify it has a new ID naming the original. Include a legacy entry without an ID and verify it is not rewritten. Restart the session and verify new IDs stay unique and references resolve.

## Claude Code and cross-runtime checks

Install by linking `skills/book-curator` into `~/.claude/skills/book-curator` only if that destination is unused. From a fresh Claude Code session started outside this repository, confirm the skill is listed and loaded from the linked path. Without touching production data, build a synthetic Curator Home in a scratch directory (never a copy of real files) and explicitly name that scratch directory as the Curator Home in the session. Verify that the session validates `settings.json`, reuses the Goodreads cache and its evidence note without a browser, checks historical Amazon snapshots with `scripts/amazon_snapshot.py` (digest and sidecar), labels them historical, and treats ownership and listing as separate from reading. Ask it to refresh Amazon or Kindle and verify it declines without opening a browser. Give fictional feedback and verify a new unique ID continues the existing sequence without rewriting earlier entries, and that the scratch copy, not production, changed. Inspect the result with Codex conventions (settings shape, feedback heading format, cache directory names and snapshot envelope are the shared contract). Report unavailable runtimes instead of claiming them.
