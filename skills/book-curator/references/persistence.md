# Optional persistent reading knowledge

Use `~/.curator/book-curator/` only when it is the user's real, user-controlled durable home and host permissions allow it; otherwise use an explicitly supplied durable location or continue without persistence. Never touch Game Curator settings or data. An existing directory or personal file is not consent. Offer one explicit opt-in for profile/feedback read and write, and a separate opt-in for raw source cache read and write. Explain that choices are recorded in settings and can be revoked. Neither is required. Do not read personal files outside the authorized scope.

When meaningful reading evidence or a reusable capture first makes persistence useful and no valid choices are recorded, offer both scopes together in a concise, optional question naming the intended location and contents. Explain that profile/feedback and raw or derived source caches are independent, may each be declined, and require host permission; offer to record the choices for future sessions. Continue answering without waiting. Do not re-offer after a valid recorded choice, a current opt-out or a decline in this session, unless the user requests a change. If settings are invalid or inaccessible, preserve them, fail closed and explain the issue when offering; never treat ambiguity as consent. If either scope is accepted and host access allows, save only that scope, reread to verify, and report any unsaved evidence. Keep unconfirmed inferences tentative.

After explicit authorization to record choices, create `settings.json` with exactly `{"version":1,"persistence":{"profileAndFeedback":true,"rawCache":false}}` adjusted to the user's choices. Both values must be booleans, with no extra fields; missing, invalid, ambiguous or unsupported settings fail closed for both scopes. Current instructions and revocation override settings. On a fresh invocation, if the real location is established and host permits, inspect only settings first; read relevant files only within valid opted-in scopes. A custom path must be explicitly supplied or retained in an authorized host-supported setting; do not search arbitrary paths. Do not infer a shared filesystem or promise durability across runtimes. This workflow is instruction-driven; cross-session behavior has not yet been independently verified.

Keep `profile.md` concise and human-editable: confirmed preferences, tentative hypotheses, current purpose and constraints, supporting experiences and conflicts, citing dated evidence. Do not promote an inference without confirmation. Read the latest relevant files before updating. After meaningful feedback, append a dated uniquely identified entry to `feedback.md` describing source, user statement or labeled paraphrase, context and correction links; distinguish completion, abandonment, ownership and reaction. Avoid duplicates, respect edits/deletions, and update the synthesis only when warranted. On concurrent edits preserve both versions or ask rather than overwriting. Use atomic replacement where supported and reread to verify; report failures.

Authorized temporary scratch normalization is distinct from retention: saving either original exports or derived personal records as a persistent cache requires raw-cache consent. Remove temporary copies after the task when no longer needed.

With separate cache consent, place source-specific captures under `cache/goodreads/` or `cache/kindle/`. Preserve original data and record source, verified account alias if any, access scope, capture and export times, method, schema version, coverage and warnings. Do not invent account identity, completeness or missing fields. The Goodreads parser's envelope is a derived snapshot, not the raw CSV. Save raw files only when authorized, as private data. Reuse suitably recent relevant evidence, disclose staleness, and refresh only when needed. Before replacement compare verified identity, scope, coverage and freshness; a failed or partial capture must not overwrite a richer one. Preserve useful partials separately. Validate parseability and envelope before atomic replacement, check for concurrent changes, reread and verify; do not claim a write succeeded until verified. Never use untrusted source text for paths. Never store credentials or tokens, sync automatically, add telemetry, or transmit raw data elsewhere. Honor inspection, correction, export and deletion requests subject to host permissions.
