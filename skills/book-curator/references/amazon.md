# Amazon Books and Docs collector

This collector reads Amazon US **Manage Your Content and Devices** Books and Docs lists. It is an experimental Codex browser-runtime collector, not an Amazon API. It does not fetch, modify or download account content. A signed-in account, English UI and a tab with `playwright.evaluate` and numbered-page locator clicks are required; verify the intended account and host permissions each run. Never request credentials or access other accounts. It does not inspect highlights, purchase transactions, or personal-document contents.

1. Open Amazon's content management interface using supported browser controls. Select **Books**, **All**, clear any search or filter using the UI, and select page 1. Verify the account and displayed category; do not assume a session is the intended account. Keep the source page read-only: never click delete, deliver, or reading-status controls. The collector does not independently verify account identity or absence of every possible filter; the caller must verify these before making coverage claims.
2. Resolve the module relative to the installed skill, not this repository checkout. Set `skillPath` to the absolute path of the installed `SKILL.md` file. In a host runtime supporting local ES-module imports and a compatible tab, run:

```js
const {pathToFileURL} = await import('node:url');
const moduleUrl = new URL('./scripts/amazon/collector.mjs', pathToFileURL(skillPath));
const {collectCategory} = await import(moduleUrl.href);
const books = await collectCategory(tab, 'books');
nodeRepl.write({coverage: books.coverage, diagnostics: books.diagnostics, warnings: books.warnings});
```

Select **Docs** and page 1 through the page UI, verify its category, then run `await collectCategory(tab, 'docs')`. Keep the two captures separate. The collector follows numbered controls (Amazon's “Next” can jump multiple pages), bounds page attempts, confirms consecutive displayed ranges, and preserves captured batches on failure. If a sign-in or human-verification challenge appears, stop automated collection and navigation immediately. Preserve completed batches and ask the user to complete it in the same browser; never solve or bypass it or switch browsers to evade it. Afterward verify account, category, filters and page; restart from page 1 if continuity is uncertain. If a selector, navigation or operation fails, follow [recovery](acquisition.md#recovery), test the same operation directly in the same session, and retain partial results. Do not silently change installed skill files. Collect only needed categories and do not send full records through model context.
3. Inspect the coverage, observed ranges and count, unique IDs, missing fields, duplicates and warnings. `complete-observed` means the captured row and unique-ID counts match the stable displayed total with contiguous ranges; it does not prove an unfiltered account, consistent snapshot under concurrent changes, or full ownership/reading history. `diagnostics.enumerationMatched` separately reports whether ranges and unique identifiers match the displayed total; missing metadata still produces `partial` even when enumeration matches. A missing count, row, field, duplicate, failed page, inconsistent total or page limit produces `partial`. The collector supports the observed US English interface; changes, zero-result pages and other locales may remain partial. Source type distinguishes `KindleEBook`, `KindleEBookSample`, and `KindlePDoc`; preserve it, labels and timestamps. An absent READ badge is unknown, not unread. Samples are not full books; a listing is not evidence of purchase, permanent ownership, completion or enjoyment. Docs may not be books. Preserve raw date/size labels and unknown values without guessing formats.
4. Keep capture in memory or a private, task-scoped staging location. Only with separate `rawCache` consent and host permission, save a **new** private snapshot using `saveNewSnapshot` from `scripts/amazon/cache.mjs`; it requires `{rawCacheAuthorized:true}`, uses exclusive creation and verifies read-back, and never replaces an existing file. Use trusted user-controlled paths such as `cache/amazon/books-<timestamp>.json` and `docs-<timestamp>.json`; choose new names safely and compare any previous capture's account, scope, date, category and coverage. A partial or unknown-account capture cannot overwrite a richer capture. If identity and scope have been verified, create a private sidecar for that exact snapshot with an approved non-secret account alias, verification evidence, category, scope, capture time and a SHA-256 digest of the snapshot bytes. Use exclusive creation, restrict access, and reread and verify the association; never modify the snapshot to claim a verified identity. The collector itself returns `account:null` and `accessScope:unknown`. In a later session, select captures by verified account, category and scope, validate the sidecar digest, then compare coverage and freshness; do not simply choose the newest file. Treat a missing, mismatched or unverified sidecar as unknown identity and scope. Never infer identity from the page URL or merge accounts. Follow [persistence](persistence.md) for consent, safe retention and conflicts.
5. Reuse relevant authorized Goodreads/profile/feedback alongside Amazon observations, with provenance. Do not automatically join works by title or infer that an accessible item is unread; distinguish editions, translations, samples and personal documents. Explain why an already accessible item fits the current purpose and note known reading history and uncertainty.
